# ADR 0006 — identity : e-mails de compte, réinitialisation, verrouillage et cache de session (4 octobre 2026)

Statut : accepté. Contexte : questions ouvertes du lot 0 (`identity`), sur des points que la spec technique laissait ambigus ou contradictoires (TEC-STK-02 réserve le SMTP à `envois`, livré au lot 2 ; aucun parcours de réinitialisation décrit ; TEC-SEC-01 verrouille par compte, ce qui permet à un inconnu de bloquer un associé ; TEC-WEB-03 met en cache la vérification de session alors qu'APP-USR-01 exige une suspension immédiate).

Décisions :
- **Exception SMTP (déroge à TEC-STK-02).** `identity` envoie lui-même ses e-mails de compte (invitation, réinitialisation, information après réinitialisation, alerte nouvel appareil TEC-SEC-19) par SMTP, et rejoint pour cela le réseau `egress-mail` (TEC-SEC-06). `envois` reste le seul service à envoyer des documents aux locataires. Lien d'invitation à usage unique, valable 7 jours, stocké haché ; aucun mot de passe dans un message ; objet « [LePalier] … » ; 5 lignes maximum.
- **Réinitialisation.** Mot de passe : lien à usage unique valable 1 h, même message à l'écran que le compte existe ou non, TOTP toujours exigé ensuite. Téléphone perdu : code de secours ; sans code de secours, le gérant réinitialise le TOTP ; si le gérant est lui-même bloqué, commande d'administration locale (documentée dans `docs/EXPLOITATION.md` au lot 6). Toute réinitialisation révoque toutes les sessions du compte et envoie un e-mail d'information.
- **Verrouillage (précise TEC-SEC-01).** 5 échecs par couple (compte, IP) = verrouillage de 15 minutes pour ce couple ; au-delà de 20 échecs par heure sur un même compte, toutes IP confondues, alerte au gérant ; limite de débit nginx par IP en amont (`limit_req`). Message unique « Trop d'essais. Réessayez dans 15 minutes. », identique pour un compte inconnu.
- **Cache de session nginx de 10 s (TEC-WEB-03 maintenu).** Une suspension ou une révocation est appliquée immédiatement dans `identity` (session révoquée en base) et prend effet à la passerelle au plus 10 secondes après. Message affiché : « Votre accès a été suspendu. Contactez le gérant de la SCI. »

Conséquences : `identity` sur les réseaux `backend` et `egress-mail` ; abstraction d'envoi d'e-mail dans `identity` (Mailpit en dev) ; recette R0-07 et R0-10 adaptées ; spec technique à mettre à jour (TEC-STK-02, TEC-SEC-01, TEC-SEC-06) au prochain export. Alternatives écartées : envoi des e-mails de compte par `envois` (dépendance au lot 2, et une fonction de sécurité qui dépendrait d'un autre service), verrouillage par compte seul (blocage d'un associé par un inconnu), suppression du cache nginx (`identity` sollicité à chaque requête).
